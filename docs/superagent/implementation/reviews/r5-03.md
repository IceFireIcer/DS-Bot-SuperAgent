# R5-03 双轴审查

- 基线：`eebccbddee0fa3b762c93fdee29b0d63113e56f4`。
- 范围：复合 WorkBrief、持久分解决定、逐项 Ticket/回执/结果、部分提交恢复、冲突与并行执行。
- Spec：GitHub #95 与 `docs/superagent/spec-r5.md` 的 R5-D02、R5-D04、R5-D12，R5-A02、R5-A03。

## Standards

首轮发现两项持久化风险：Ticket 与映射先提交、accepted item 回执后写入的窗口可能让 Worker 成功通知看到 routing 回执；R5-02 遗留 routing WorkBrief 没有 `sourceEventId`，新路径会将其误拒绝。修复后，结果刷新会按原子 Ticket 映射补齐稳定 accepted 回执，成功通知缺少 Ticket 时不再通过当前结果校验；旧 WorkBrief 在保存分解决定的同一事务内补齐来源身份。回归覆盖回执写失败但 Worker 先完成，以及旧 routing WorkBrief 恢复。复审剩余 0。

## Spec

首轮发现两项产品缺口：分项 Trigger 只含摘要，Worker 无法通过 `read_context` 补读不可变原始 Main 请求；两张卡仍用同一 WorkBrief ID 作 React key。现在每个分项 Trigger 保留原始请求、目标、约束和验收，`sourceEventId` 继续关联唯一来源；源码和生成客户端以持久 `workItemId` 匹配卡片。复审剩余 0。
